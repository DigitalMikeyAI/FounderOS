# FounderOS Engineering Constitution

## Purpose

Software can be rewritten.

Technologies will change.

Features will evolve.

But the principles used to build FounderOS must endure.

This Constitution exists to preserve the engineering culture of FounderOS so that every contributor—human or artificial—builds with the same commitment to truth, discipline, humanity, evidence, simplicity, respect, and long-term thinking.

## Engineering Belief

Great software is not created by adding more capability.
It is created by adding the right capability at the right time for the right reason.

## Engineering Mindset

A FounderOS engineer does not begin with "How do we build this?"

Instead, they follow a disciplined sequence:

- Should this exist?
- What problem does it solve?
- What is the smallest truthful implementation?
- Who should own this responsibility?
- Only then: How should it be implemented?

This sequence privileges judgement before execution.

Engineering Question

Every capability should answer one important question.

FounderOS avoids building collections of unrelated features. Each capability exists to solve a clearly defined problem, with a single primary responsibility. Simplicity of purpose leads to clarity of architecture.

## Core Values

- Truth — say what is real and avoid fabricated certainty.
- Discipline — prefer small, reversible changes over sweeping rewrites.
- Humanity — preserve dignity and the Commander's authority in every interaction.
- Evidence — base decisions on observable data and explicit inputs.
- Simplicity — choose solutions that are clear, maintainable, and minimal.
- Respect — treat collaborators, users, and systems with care.
- Long-term Thinking — optimize for durable, composable outcomes.

## The Smallest Truthful Implementation

FounderOS prefers the smallest implementation that is useful, honest, and maintainable. Complexity must earn its place. When in doubt, choose the narrower, testable path that preserves option value.

## Philosophy Before Architecture

Our lifecycle follows explicit stages:

Discovery
↓
Capability Philosophy
↓
Founder Review
↓
Capability Document
↓
Architecture Review
↓
Implementation
↓
Verification
↓
Documentation Closeout
↓
Commit
↓
Push
↓
Retrospective

Code is the expression of decisions already made. Architecture and philosophy come first; code follows and makes those decisions durable.

## Intelligence Is Earned Before It Is Expressed

This principle guides AI behavior, engineering judgment, documentation, and architecture. Insights should be grounded in evidence before they are presented as recommendations. Acceleration without earned intelligence risks harm.

## Documentation Is Part of the Product

Documentation is engineering, not paperwork. Good docs reduce cognitive load, preserve institutional memory, and make the project safer and faster to change.

## AI Collaboration

Humans provide vision, authority, and final judgment.
AI provides acceleration, implementation capability, and expertise within defined boundaries.

Architecture provides ownership and constraints. No AI replaces human engineering judgment. AI is a collaborator, not an owner.

## Architecture Principle

Prefer extending existing systems. Before creating a new system, workflow, or data model, ask: "Does an existing owner already exist?" Avoid duplication of responsibility.

## Git Authority

Git history is institutional memory. Commits and pushes are acts of record and require explicit authorization. Preserve meaningful history; do not commit noise.

## Definition of Done

A capability is complete only when:

its purpose is understood
its philosophy is documented
its architecture has been reviewed
its implementation is verified
its documentation matches reality
its history is intentionally recorded

## Mentorship

"A FounderOS engineer should never leave another engineer feeling lost, alone, or confused because of FounderOS or Archie."

Every contributor must improve the codebase and the people who work within it. Mentorship applies to human-human and human-AI collaboration.

## Engineer's Oath

We pledge to:

- pursue truth before assumption
- favor clarity over cleverness
- extend before replacing
- document before expanding
- verify before declaring success
- preserve the Commander's authority
- earn intelligence before expressing it
- leave every system — and every engineer — better than we found them

## Closing Principle

Every contributor inherits this Constitution with two responsibilities:

To preserve the principles that made FounderOS trustworthy.

And to leave the engineering culture stronger than they found it.

Great software can be rewritten.
Great engineering culture must be preserved.
